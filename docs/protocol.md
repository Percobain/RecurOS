# ContextOS wire formats (normative)

Everything that crosses a process or machine boundary. The Rust binary, the
Cloudflare Worker and the browser extension all implement against this file.

## 1. Store layout (`~/ctx`, a git repo)

```
log/<machine-id>/<YYYY-MM>.jsonl   append-only; ONE writer per directory
log/cloud/<YYYY-MM>.jsonl          written only by the Worker
refs/branches.yaml                 branch DAG (see §5)
refs/active                        "project/branch" used by chat surfaces
refs/weights.yaml                  optional packer weight overrides
packs/index.md                     compiled index (≈250 tokens)
packs/<project>/<branch>.md        compiled dossier per branch, for chat surfaces
.cache/                            gitignored, disposable
.machine                           gitignored, this machine's shard name
```

`packs/` is regenerated by `ctx sync` before every commit, so the Worker can
serve compiled packs without re-implementing the packer.

## 2. Log records

One JSON object per line, UTF-8, `\n`-terminated. Every record has a `rec` tag.
Readers must skip (with a warning) lines they cannot parse or whose tag they
don't know. Timestamps are RFC 3339 UTC. Ids are ULIDs.

### `claim`

```json
{"rec":"claim","id":"01K...","cid":"b3:<64 hex>","kind":"decision",
 "branch":"sovereign/code","text":"...","why":"...","refs":["..."],
 "entities":["..."],"supersedes":"01K...","status":"active",
 "confidence":"medium","src":"cli","t_valid":"...","t_tx":"...","tokens":12}
```

Optional (omitted when empty): `why refs entities supersedes helpful harmful last_used`.
`cid` is computed per [canonical.md](canonical.md) and **must** match; readers
drop claims whose cid does not verify. `text/why/refs/entities` are stored
already normalised. `tokens = ceil(chars(text)/4)`.
`status` is `active` for normal writes and `proposed` for proposals.

### `status` — a status transition

```json
{"rec":"status","id":"01K...","claim":"01K...","to":"archived",
 "reason":"optional text","src":"cli","t_tx":"..."}
```

Effective status of a claim = max over its own `status` and all transitions,
in the total order `proposed < active < superseded < rejected < archived`.
A claim with `supersedes: X` implies a transition of X to `superseded`.
This is order-independent, so any interleaving of shards converges.

### `counter` — helpful/harmful G-counter state

```json
{"rec":"counter","id":"01K...","claim":"01K...","machine":"laptop",
 "helpful":3,"harmful":0,"t_tx":"..."}
```

Absolute per-machine values; merge is per-machine max, read is the sum.

## 3. `ctxd` local HTTP API

Binds `127.0.0.1:7777` only. Every request except `GET /v1/health` requires
`Authorization: Bearer <token>`, where the token is the contents of
`~/.ctx/token` (created by `ctx init` / `ctxd`). Responses are JSON unless noted.

| Method & path | Body / query | Response |
|---|---|---|
| `GET /v1/health` | — | `{"ok":true,"version":"x.y.z"}` |
| `GET /v1/branches` | — | `{"active":"p/b","branches":[{"name":"p/b","claims":12}]}` |
| `GET /v1/pack` | `branch?`, `task?`, `budget?`, `for?` (`dossier` default, `agents-md`, `prose`, `index`) | `text/markdown` |
| `GET /v1/search` | `q`, `branch?` | `{"claims":[Claim,...]}` |
| `POST /v1/claims` | `{"branch?":"p/b","src?":"chatgpt","claims":[{"kind","text","why?","refs?","entities?"}]}` | `{"saved":[{"id","cid"}],"duplicates":[{"id","cid"}],"errors":["..."]}` |

`branch` defaults to `refs/active`, then `default`.

## 4. The `ctx-claims` fence (browser → ctx)

A model asked to "ctx save" answers with exactly one fenced block:

````
```ctx-claims
[{"kind":"decision","text":"...","why":"...","refs":["..."]}]
```
````

`kind` is one of `fact decision rejected constraint question claim`; `why` and
`refs` are optional. Consumers: the extension (→ `POST /v1/claims`) and
`ctx save --paste` (clipboard). A bare JSON array without the fence is also
accepted by `ctx save --paste`.

## 5. `refs/branches.yaml`

```yaml
sovereign:
  research:
    holds: [fact, question, claim, rejected, decision]
    budget: 1200
    compile: dossier
  code:
    parent: research
    holds: [decision, constraint, rejected, question]
    inherits: { research: [decision, constraint] }
    budget: 700
    compile: agents-md
    binds: [claude-code, codex, cursor]
    pins: []          # claim ids always included in packs
    archived: false
```

Full branch name is `<project>/<branch>`. Claims written before branches
existed live on the unscoped branch `default`, which holds every kind.

## 6. Cloudflare Worker (claude.ai / ChatGPT connector)

Stateless MCP over HTTP at `POST /mcp/<CTX_SECRET>` (JSON-RPC 2.0, JSON
responses, no sessions). Reads and writes the private GitHub repo holding
`~/ctx` through the GitHub REST API. Exposes the same five tools as the local
server:

| Tool | Worker behaviour |
|---|---|
| `ctx_index()` | return `packs/index.md` |
| `ctx_pack(branch, task?, budget?)` | return `packs/<branch>.md`; if `task` is given, append up to 20 matching claims found by keyword search over the log |
| `ctx_search(query, branch?)` | keyword search over all `log/**/*.jsonl` |
| `ctx_append(branch, kind, text, why?, refs?)` | build a claim (canonical CID, ULID), append to `log/cloud/<YYYY-MM>.jsonl` via the Contents API (retry on 409) |
| `ctx_propose(target_branch, kind, text, why?)` | as `ctx_append` with `status: "proposed"` on `target_branch` |
